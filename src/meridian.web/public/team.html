Three rules read this first

Follow these and nothing you do can damage the project. Everything else on this page is just detail.

1

Never push to main

You work on your own branch and push that. Hasitha merges it in. If main breaks, all four of us are blocked.

2

Never type --force

Not with push, not with anything. A force push can permanently delete someone else's work and it cannot be undone. If a command is rejected, stop and ask.

3

Only touch your own files

Each person has their own folders, listed below. Two people editing one file is what actually causes conflicts. Stay in your area and merging is effortless.

Good news

Committing is safe. Once you have run git commit, your work is recorded and recoverable even if something later goes wrong. Commit often.

Commit 1

Postman environment

In Postman, create an Environment named Meridian with two variables: baseUrl set to https://meridian-talent.pages.dev/api, and token left empty. Export it into the postman/ folder as meridian.environment.json.

git add postman/meridian.environment.json
git commit -m "Add Postman environment with base URL and token variables"
Commit 2

Authentication requests

Create a Collection called Meridian API, with a folder Auth containing a login request for each of the four roles, plus register and /me.

On the login request open the Scripts (or Tests) tab and paste this. It saves the token automatically so every later request is signed in:

pm.test("Login succeeds", () => pm.response.to.have.status(200));
pm.environment.set("token", pm.response.json().accessToken);

Then set the Collection's Authorization to Bearer Token with the value {{token}}. Export the collection into postman/.

git add postman/meridian.collection.json
git commit -m "Add authentication requests to the Postman collection"
Commit 3

Job posting requests

Add a Jobs folder with: search, my postings, get one, create, publish, duplicate. Copy example bodies from the live Swagger page.

Do not skip

On publish and duplicate, set the body to {} as raw JSON. They take no body, but the live server rejects an empty POST with 411 Length Required. This will waste an hour if you miss it.

git add postman/meridian.collection.json
git commit -m "Add job posting lifecycle requests to the collection"

If something goes wrong do not panic

Nothing is lost as long as you have committed. Find your situation below.

I committed to main by mistake and have not pushed

git branch work/YOURNAME       # save your work onto a branch
git reset --hard origin/main   # put main back to normal
git checkout work/YOURNAME     # carry on there

My push was rejected because main moved on

git pull --rebase origin main
# fix any conflicts it reports, then
git push

I am completely lost

Stop. Do not run anything containing --force, reset --hard or clean. Run the command below and send the output to the group. It can be recovered.

git status
git log --oneline -10

How do I check my work is safely committed?

git status should say nothing to commit, working tree clean, and your commits should appear at the top of git log --oneline.
